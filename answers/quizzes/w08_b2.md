## Part 2: Interview questions

### 1. Walk me through how logistic regression is trained: the model, the loss, why that loss, and the gradient.

**Strong answer:** The model computes a linear score $z = \mathbf{w}^\top\mathbf{x} + b$ and maps it through the sigmoid to a probability $p = \sigma(z)$, so the score is
the log-odds. It is trained by maximum likelihood. Treating each label as a Bernoulli draw with probability $p_i$, the
negative log-likelihood is the log-loss $-[y\log p + (1 - y)\log(1 - p)]$, averaged over examples. Squared error would give a non-convex
objective with flat gradients for confident mistakes. Log-loss is convex and punishes confident mistakes hard. The
gradient simplifies beautifully: $\partial\ell/\partial z = p - y$, so $\nabla_{\mathbf{w}} = \frac1n\mathbf{X}^\top(\mathbf{p} - \mathbf{y})$, the same form as linear regression. There is no closed form, so we use
gradient descent or a quasi-Newton method like lbfgs, with an L2 penalty by default. In code, compute the loss from
logits with `logaddexp` to avoid `log(0)`.
**Weak answer:** "It's linear regression with a sigmoid on top. You minimize the error with gradient descent until it
converges, and then threshold at 0.5."
**Why the weak one fails:** it does not name the loss, cannot justify it (likelihood, convexity), gives no gradient, and
misses the regularization and numerical points an interviewer is probing for.
**Follow-up an interviewer would ask:** "Derive $\partial\ell/\partial z = p - y$ on the whiteboard", or "What happens to the weights if the data is perfectly separable?"

### 2. Your fraud model is a logistic regression. A new feature makes training accuracy jump to 100% and the coefficients explode. What are the possible explanations, and what do you check first?

**Strong answer:** Exploding coefficients with perfect training accuracy is perfect separation: the new feature (alone
or with others) splits fraud from non-fraud exactly, so the unpenalized likelihood has no maximum. First suspect
leakage. A feature that perfectly predicts fraud is usually recorded after the fact (a chargeback flag, a "case
opened" timestamp, an account status changed by the fraud team). So I check when and by which process the feature is
written, relative to the prediction time, and compute its single-feature AUC on a time-based split. If it is
legitimate, it may be a rare category that occurs only in fraud rows of a small training set, which the model will
overfit. Either way, keep an L2 penalty and validate on later data. Validation log-loss, not training accuracy, says whether the feature helps.
**Weak answer:** "The model is overfitting, so add regularization or remove the feature."
**Why the weak one fails:** it treats a symptom. It never names separation or, more importantly, leakage, which is the most likely cause in
fraud data and which regularization would hide rather than fix.
**Follow-up an interviewer would ask:** "The feature turns out to be legitimate but rare. How do you keep it without overfitting?"

### 3. Compare L1 and L2 regularization. When would you choose each, and what is elastic net for?

**Strong answer:** Both add a penalty on weight size to the loss and are chosen by cross-validating its strength. L2
(ridge, $\lambda\lVert\mathbf{w}\rVert^2$) is a Gaussian prior. It shrinks all weights smoothly, never to exactly zero, has a closed form for linear regression,
stabilizes collinear features by making them share credit, and makes separable classification problems solvable. L1
(lasso, $\lambda\lVert\mathbf{w}\rVert_1$) is a Laplace prior. Its constant push sets weights exactly to zero, so it selects features and gives sparse, cheaper
models, but among correlated features its choice is unstable, close to arbitrary. Choose L2 when you expect many
small effects or care about stable weights; L1 when you expect a few features to matter and want sparsity. Elastic net mixes
both: sparsity from L1 with the grouping of correlated features from L2. It is the usual choice for wide data with
correlated groups, such as text n-grams or one-hot blocks.
**Weak answer:** "L1 uses absolute values and L2 uses squares. L1 is for feature selection and L2 is for preventing overfitting."
**Why the weak one fails:** both prevent overfitting; the answer gives no mechanism (why zeros), nothing on collinearity
or instability, no Bayesian reading, and does not say what elastic net is for.
**Follow-up an interviewer would ask:** "Why does L1 give exact zeros? Draw it", or "You ran the lasso twice on bootstrap samples and got different features. Why?"

### 4. Why must features be standardized before fitting a regularized linear model, and why is the intercept not penalized? What goes wrong if you get either wrong?

**Strong answer:** The penalty compares the sizes of the weights, but a weight's size depends on its feature's units:
the same effect is a weight of 3 per kilogram or 0.003 per gram. Without standardizing, features in small units
(large weights) are penalized heavily and features in large units escape the penalty, so the regularization reflects
measurement units rather than importance. In the quiz example, the lasso shrank one feature and left an equally important one untouched.
Standardize inside a pipeline so the scaling is refitted in each fold. The intercept is not penalized because it only
sets the overall level of the predictions: shifting every target by 100 should shift the intercept by 100. Penalizing it
pulls predictions towards zero instead of the mean, biasing every prediction, and badly so when the target's mean is far from 0.
**Weak answer:** "Standardizing helps the optimizer converge faster, and the intercept is just a constant so it doesn't matter."
**Why the weak one fails:** faster convergence is true but secondary. It misses that unscaled features change *which* model is
selected, and it gives no reason for leaving the intercept unpenalized or the bias that results.
**Follow-up an interviewer would ask:** "Do tree models need standardization? Why not?"

### 5. We want to show "similar products" using nearest neighbours on 300 product features for 10 million products. What could go wrong, and how would you build it?

**Strong answer:** Three classes of problem. *Meaningless distances:* raw features on different scales and with
heavy tails (prices, counts) let a few columns dominate. So transform (log), standardize, and decide feature-group
weights deliberately; and 300 features invite the curse of dimensionality (distances concentrate, irrelevant features
add noise). I would rather learn a dense embedding (from co-purchase or co-view data, or a text/image encoder), use
cosine similarity, and check the nearest/farthest distance ratio. *Scale:* exact search over 10 million vectors per request
is too slow. Use an approximate index (HNSW, IVF) in a vector store or pgvector, precompute neighbours offline for the
popular items, and measure recall@k of the approximate search against exact search on a sample. *Quality:* "similar"
has to be defined by an outcome. Evaluate offline with click or co-purchase data (precision@k, NDCG) against a simple baseline such as
the same category, then A/B test. Also handle new products with no behaviour data (cold start) via content features.
**Weak answer:** "Standardize the features and use scikit-learn's `NearestNeighbors` with k = 10. It's simple and works."
**Why the weak one fails:** brute-force search does not scale to 10 million items at request time; it ignores high-dimensional and
heavy-tailed features, and says nothing about evaluation.
**Follow-up an interviewer would ask:** "What does an approximate index trade away, and how would you tune it?"

### 6. Naive Bayes assumes independence that is clearly false for text. Why does it still work, and when would you not trust its output?

**Strong answer:** Naive Bayes multiplies per-word likelihoods as if the words were independent given the class, which turns
the posterior log-odds into a sum of per-word log-ratios: a linear classifier whose weights are set by counting. For
classification only the sign of the log-odds matters. The independence violation mostly inflates the magnitude, since
correlated words each add their full weight, and often leaves the sign right, so accuracy can match logistic
regression. It also needs little data, because each weight is estimated separately. I would not trust its
probabilities: they are pushed to 0 and 1, so log-loss is poor and any threshold like "auto-act above 95%" is
miscalibrated. Calibrate on held-out data or use a discriminative model when probabilities drive decisions. It also
degrades with heavily duplicated or redundant features and when the vocabulary drifts.
**Weak answer:** "It works because words are mostly independent in practice, and it's fast."
**Why the weak one fails:** the premise is false. Words are strongly dependent. The answer misses the real reason (only the
argmax must be right) and the practical consequence (overconfident probabilities).
**Follow-up an interviewer would ask:** "What is Laplace smoothing and what happens without it?"

### 7. Explain the kernel trick. Why can an SVM use it, and what does the RBF kernel's $\gamma$ control?

**Strong answer:** In the SVM's dual form, both training and prediction touch the data only through dot products
$\mathbf{x}_i^\top\mathbf{x}_j$. The prediction is $f(\mathbf{x}) = \sum_i\alpha_iy_i\mathbf{x}_i^\top\mathbf{x} + b$ over the support vectors. If we replace each dot product by a kernel $k(\mathbf{x}, \mathbf{z})$ that equals
$\boldsymbol{\phi}(\mathbf{x})^\top\boldsymbol{\phi}(\mathbf{z})$ for some feature map $\boldsymbol{\phi}$, we get a linear SVM in $\boldsymbol{\phi}$-space, which is non-linear in the original space, without ever computing $\boldsymbol{\phi}$. For example,
$(\mathbf{x}^\top\mathbf{z})^2$ in 2-D equals the dot product of $(x_1^2, \sqrt2x_1x_2, x_2^2)$. The RBF kernel $e^{-\gamma\lVert\mathbf{x} - \mathbf{z}\rVert^2}$ corresponds to an infinite-dimensional $\boldsymbol{\phi}$, yet costs one distance. The decision function becomes a sum
of Gaussian bumps on the support vectors. $\gamma$ sets the bump width: large $\gamma$ means narrow bumps and a wiggly boundary that can overfit;
small $\gamma$ means wide bumps and a nearly linear boundary. It must be tuned jointly with $C$, on standardized features.
**Weak answer:** "The kernel trick maps the data to a higher dimension where it becomes linearly separable. RBF is the most common kernel."
**Why the weak one fails:** it describes the effect but not the trick: no mention that only dot products are needed,
that $\boldsymbol{\phi}$ is never computed, or what $\gamma$ does.
**Follow-up an interviewer would ask:** "Why don't kernel SVMs scale to millions of rows?"

### 8. Logistic regression or a linear SVM: how do they differ, and how would you choose between them in practice?

**Strong answer:** Both are linear classifiers with an L2 penalty; they differ in the loss. Logistic regression uses
log-loss, which never reaches zero, so every point influences the fit and the output is a calibrated-ish probability.
The SVM uses the hinge loss, which is zero beyond the margin, so only the support vectors matter, the solution is
sparse in the training points, and the output is an uncalibrated score. In practice their accuracies are usually
within noise of each other (in the B2.5 lab, one or two tumours). So I choose on the requirements: logistic regression
when I need probabilities (risk scores, expected-cost thresholds, combining models), interpretable odds ratios, or
easy multiclass; a linear SVM when only the decision matters and the data is large and sparse (text), where
`LinearSVC` is fast. I would also note that scikit-learn's `LinearSVC` defaults to the squared hinge and penalizes the intercept.
**Weak answer:** "SVMs are more accurate because they maximize the margin, so I'd use an SVM unless I need speed."
**Why the weak one fails:** the accuracy claim is not generally true, and it ignores the decisive practical difference:
probabilities and calibration.
**Follow-up an interviewer would ask:** "How would you get probabilities out of an SVM, and what does that cost?"
